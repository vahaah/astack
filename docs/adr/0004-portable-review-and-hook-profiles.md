# 0004. Portable review packs and explicit quality profiles

Status: Accepted
Date: 2026-10-27
Ticket: none
Supersedes: none

## Context

The public source has one astack plugin and one build for each supported client.
The catalog rewrite removed every moved-prose STE exemption.
Each retained skill needs its full body, references, invocation contract, and upstream credits.
The ECC additions must use the same source across those builds.

## Decisions

### D1. Keep one catalog and its complete behavior

Each skill has one nonempty title before useful body content.
Every skill and agent follows the house style.
The four quoted comment-rule sections and licence text retain their upstream wording.
Keep the shrink-only exemption cap at 0.

### D2. Add scoped rules and optional read-only reviewers

Use original TypeScript/TSX and PostgreSQL packs.
The anonymous language census supports these two scopes.
Each reviewer inherits its model and can use only Read, Grep, and Glob.
Portable clients receive the same review criteria as skill references.
One shared rule list supplies installation, migration, doctor, and distribution selection.
Keep detailed checklists outside the existing 10240-byte fragment limit.

### D3. Make quality profiles explicit

The hooks profile is strict by default.
Minimal disables only the STE, type, and comment quality groups.
An explicit boolean overrides its preset.
Invalid input reports its field and retains strict runtime behavior.
Filter disabled handlers before they can write state.
All unmarked handlers remain required.

The comment module also checks STE in kept comments.
Disabling STE skips that nested check.
Disabling comments skips the whole comment module.
When types are disabled, comments still enforce their own suppression rule.
Turn bookkeeping always saves cron prompts and advances the turn.
CLI and CI checks remain independent of hook profiles.

### D4. Revalidate Cursor records against their original baseline

Each record identifies its session, canonical workspace, handler, and canonical target file.
Keep its first blocked before-content until a fresh check resolves it.
Read current files at stop, including corrections outside Cursor.
A refresh writes no STE attempt or reply claim.
Disabled quality records remain dormant for later revalidation.
A partial comment check keeps its baseline while nested STE is disabled.
A suppression handoff carries the baseline to the active type checker and respects its current kernel permissions.
Deleted files resolve records.
Unreadable files and unavailable handlers report a verification limit.

Old string-only records have no reliable provenance.
Deliver them once as unverified reports without guessing their handler or scope.
Store baselines only in private local state.
Never include them in public release evidence.

### D5. Compare fresh expected artifacts without writes

One bundle helper owns the Node target and whitespace-minification options.
The drift check compiles fresh source in memory.
It supplies those bytes to both bundle inputs before rendering expected builds.
Compare all generated paths, bytes, and executable bits.
Reject missing, extra, stale, and linked output files.
Keep generated bytes, modes, and mtimes unchanged.

## Consequences

The same scoped guidance reaches native and portable clients.
Quality settings cannot weaken required workflow guards.
Cursor reports current findings while retaining unresolved baseline differences.
The drift check detects a stale source bundle even when its dist copies match it.

Static builds and synthetic journeys do not prove a live client install.
Keep authenticated load tests, hosted CI, and owner installation checks as separate evidence.
