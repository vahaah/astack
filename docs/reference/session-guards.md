## Acceptance criteria

- [criterion:SG-merge-grant] A merge needs a grant. A grant comes from `merge.authority` or `merge.standingBases` of the profile on the PR base branch, or from a person's prompt in the current turn. That prompt has an un-negated merge word or "full send" clause.
- [criterion:SG-base-authority] The standing grant and `merge.requireChecks` come only from `.astack/profile.json` at the tip of the PR base branch. An absent or unreadable file gives turn authority. A working-tree edit changes no merge verdict, and a standing profile covers only the PRs of its repo.
- [criterion:SG-framed-prompt] A prompt that opens with a tag, or with a bracket label that is not a Markdown link, gives no grant. A host `source` of `user` still counts. A Cursor prompt gives a grant only in an attended session.
- [criterion:SG-mcp-merge] Each MCP tool with a merge word in the server name or the tool name gets a deny, also with a grant. A state word such as `merged` passes only with a read verb and no write verb. A read tool on a merge request, such as `list_merge_requests`, passes. An MCP input that holds a `gh pr merge` command or a `gh api` merge gets a deny too. So does a click tool whose input names a merge button.
- [criterion:SG-guard-error] An error of the merge guard on a merge command or an MCP merge tool gives a deny that names the error. Each other handler fails open.
- [criterion:SG-full-stop] A "full stop" clause and a negated merge or "full send" clause give no grant. The full-stop procedure never merges. A prompt from each source can start the full-stop run. Then the merge guard denies each `gh pr merge` until the next prompt of a person, also with a standing grant. The prompt has `/astack:full-stop` at its start, or "full stop" as its only instruction. `--disable-auto` passes. With no path for the full-stop record, a standing grant merges nothing.
- [criterion:SG-unattended] In an unattended session, a prompt with no source field gives no grant. The merge denial and `astack doctor` name the variable that makes the session unattended. A prompt with the source `user` gets the attended note.
- [criterion:SG-scratch] The type, comment and doc STE hooks skip a write or an edit only when its file is a scratch file.
- [criterion:SG-commit-surface] The comment and type hooks examine each path that a commit includes, also a scratch file.
- [criterion:SG-work-loss] The destructive hook denies a git command that discards uncommitted work in the whole tree or in a folder. A bound session repo is the exception. Each denial names work that git discards. `git apply -R` from stdin, `git read-tree -u --reset`, `git checkout-index -a -f` and `git archive` piped to `tar -x` are such commands.
- [criterion:SG-session-repo] A broad discard on the dirty tree of a repo that `git init`, `git clone <url>` or `git worktree add <path>` made in this session passes in a later call. A force-push to `main`, `supabase db reset` and a commit with `--no-verify` keep their denies there. A `git clean -ffd` that removes a nested repo with no bound record gets its deny. So does a discard of a dirty submodule with no bound record. In a repo with a submodule, a command that recurses into submodules gets no exemption.
- [criterion:SG-session-repo-identity] A reset gets a deny in a dirty repo that another process made at a dropped pending path. So does a reset after another process swaps the git dir of a bound repo. A git dir, a `.git` marker, a `HEAD`, an index entry or a reflog entry older than the call stops the bind. A symlink or a new dirty repo at the path of a bound record gets a deny too. So does a dirty repo that the call of the init moved to its path. A repo that `--separate-git-dir` made gets no record. Neither does a target that `cp`, `mv`, `rsync` or `tar` writes into in the same line. A write into `<state>/session-repos/` gets a deny. In a dirty session repo, a discard with `--git-dir`, `--work-tree`, a `core.worktree` key or a place variable gets the deny of ADR 0010 D3. A place variable in any step of the line counts too, and so does a step such as `declare`, `set`, `eval`, `source` or `trap` in any order. A dynamic word, a glob, a brace expansion or a backslash in any word of the line also gives that deny. So does a `tar -x` after `git archive` with a flag such as `-C` or `-P`. A `git archive` step with `--prefix`, `--remote`, `--add-file`, `--add-virtual-file` or a tree-ish with a path gets that deny too. In a session repo, the extraction keeps each dirty nested repo and submodule with no bound record.
- [criterion:SG-session-repo-closed] The discard after `git init` gets a deny with no usable record. That is no session id, an id with a slash or a state folder that refuses a write. A pending entry that binds in a call whose save fails passes the discard of that call.
- [criterion:SG-session-repo-total] Four record faults throw nothing. Two are a record file that is a folder and a record of a wrong shape. The other two are a state path and an init target that are files. With each fault, a force-push to `main` and a discard in another dirty repo in one call get their denies.
- [criterion:SG-plain-form] The merge guard and the destructive guard judge the plain form of each shell step. A known wrapper, a brace group, an `if` and a static `sh -c`, `eval` or substitution body give the verdict of the plain command.
- [criterion:SG-stdin-source] A shell step reads its stdin script only from one quoted heredoc, one static here-string or one whole pipe stage. Each other stdin source makes the step unreadable. Such sources are a file, an fd, a second source and a stdin redirect on a group, a subshell, a loop or a bare `exec`. A redirect fd is a number, so `00<` reads fd 0.
- [criterion:SG-unknown-dollar] Bash reads a `$` before a blank, a newline, an operator other than `(`, a closing quote or the end as text. `$"..."` reads as a double-quoted string. Each other `$` form makes its word dynamic, so a guarded verb or `gh pr merge` with such a word is unreadable.
- [criterion:SG-dynamic-word] A guarded verb that a variable or a substitution hides is unreadable. An unreadable work-loss command gets a deny on a changed tree when astack can read its folder. Each other unreadable guarded verb gets a deny at once.
- [criterion:SG-api-merge] Each `gh api` merge of a PR gets a deny. A GraphQL body with a merge mutation or a dynamic field gets a deny. So does a body from a pipe or a file that the hook cannot read. A write call to an endpoint that a variable gives gets a deny too. A word after `api` with an unquoted glob or brace expansion gets a deny too, also in a read. A glob or brace in the program gets a deny with no text check. So does one in a `gh` word up to the subcommand or after `pr merge`. An unquoted variable after `api` gets a deny too. A variable in double quotes passes only in a read with one endpoint and no write flag. Only `"$name"`, `"${name}"` and `"${name[index]}"` count as one argument.
- [criterion:SG-hook-skip] `--no-verify`, `HUSKY=0`, `LEFTHOOK=0` and a `core.hooksPath` folder where HEAD does not hold each active hook as an executable file skip the git hooks. A `core.hooksPath` with a `..` segment or a symlink is a hook skip too. Static `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>` pairs below a static `GIT_CONFIG_COUNT` count as `-c` values. Each other `GIT_CONFIG` variable is a hook skip. So is an `include.path` or `includeIf.<cond>.path` key from each source. A `HUSKY` or `LEFTHOOK` value that a variable gives or that an earlier export form exports is a hook skip too. The export forms are `export`, `declare -x`, `typeset -x`, `set -a` and `set -o allexport`. Each hook skip on a commit, a push or a config write gets the owner gate.
- [criterion:SG-hooks-path] A `core.hooksPath` target passes when git uses it now. Else HEAD holds at least one hook there as an executable file. Each active hook then needs an executable file of its name there with the same bytes. A working-tree change under the target is a hook skip.
- [criterion:SG-gates-run] `astack gates run` records HEAD only when each gate that applies exits 0 on a clean tree. The record holds the profile blob at the merge base of the base and HEAD, and a HEAD with another blob gets no record. A hook-skip push passes only when the source and its merge base with the record base hold that blob. A record with no blob gives the owner gate.
- [criterion:SG-gate-folder] A Write call or an Edit call into `<state>/gates/` gets a deny. So does a shell step with a static word or an output redirect target there. A read with a program such as `cat`, `ls` or `jq` passes.
- [criterion:SG-generated] Each generated file and each bundle of the CLI equals a fresh build of its source.
- [criterion:SG-runtime] `bin/astack` runs the first runtime that it finds, with bun before node, and probes no version before a run. Below node 22, a hook exits 0 with one line on stderr, and each other command exits 1.
- [criterion:SG-conformance] For each row of the model tables, the real guards give the verdict of the mirror. The tables hold the commands, the changes, the push targets, the merges and the file facts. Generated command runs give the verdicts and the trees after git of the model. A hand mutation of `grantReasons` fails the conformance test.
- [criterion:SG-preserve] A change to a skill, a doc or another command leaves the verdicts of the session guards unchanged.

## Claim boundary

The model covers a finite set of prompts, paths, changes and git commands.
It takes the observations of the hooks as true.
The implementation controls examine the clause grammar, the shell parser and the git status reader.
The model takes the plain form of each shell step as given. A property test checks the wrapper law of the parser.
The session repo rule holds under three premises.
No other process makes a repo at a pending path before the next Bash call of the session.
The host runs a Bash call to its end before the PreToolUse hook of the next Bash call.
The host keeps one session id for the life of a session.
The merge guard keeps a full-stop record in the state folder. The record stops a mistake, not a hostile agent, because an agent can delete it.
The conformance test and the fast-check commands examine the real guards against the tables of the model. They do not show that each other code path refines the model.
