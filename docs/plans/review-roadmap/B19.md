# The full check ends in under 60 s, and each PR commit gets one CI run

This block cuts the wait of each gate run.
It gives the speed part of the M2 demo.
`bun run check` takes less than 60 s on the dev machine, and `check:fast` has a fixed cap of 20 s.

## Goal

Goal. A type error fails `bun run check` in under 2 s, and the full check ends in under 60 s on the dev machine. Each PR commit gets one CI run.
Decision. Can an agent run the full gate before each push and get the answer in one minute?
Done when. The median of 3 timed `bun run check` runs on the session branch is under 60 s. Today one run takes 227.6 s.

## Scope

- In. The gate order and one proof run in `package.json`, the parallel suite with a 20 s timeout, and `check:fast` with a fixed 20 s cap.
- In. The proof starts the TLC triple together, judges it in order and kills the live runs when that order gives a result. The timeout control uses 200 ms, and ADR 0005 gets dated notes.
- In. A merge base for a local run of `scripts/check-proof.ts` when `origin/HEAD` resolves.
- In. A push trigger on main only in `check.yml`, and a last CI step that also fails on an untracked path.
- In. A launcher with no version probe before a run, and one floor rule for the launcher and the CLI entry.
- Out. The fixture reuse in the heavy test files, also in the two change-proof files. B20 owns it and removes the 20 s timeout.
- Out. A verdict cache, a cut of the restored run and the risk ladder. B06 owns the ladder.
- Out. The node compile cache for hooks, and a blob cache for the neutrality and secrets scans.

## How each step runs

- Steps 4 and 5 start with a test that fails for the reported reason. Step 5 turns the scratch repo of the Context into that test.
- Step 2 changes the speed and keeps the behaviour. Its red check is a timed `bun run check:proof` at 3.3 s, and its green check is under 2 s.
- In step 2, the two new controls put a fake `java` in `JAVA_HOME`. The order control holds the positive run until the negative run ends, so a first-to-end judge fails it under any load. The stop control fails the positive run at once and holds the negative run.
- In step 4, the CLI entry compares the node version with the floor. `doctor.ts` and `scripts/build.ts` import `NODE_FLOOR` from `floor.ts`. A launcher test compares the launcher `floor` with `NODE_FLOOR`.
- In step 4, a hook run that exits with a status other than 0 or 2 gets one version probe. Below the floor, the launcher prints its message and exits 0. A Cursor event gets the allow JSON.
- In step 5, a clean HEAD has no diff, no staged change and no untracked path, the three sets of `changedPaths`. An `origin/HEAD` that does not resolve counts as none. A shallow clone with no `HEAD^` keeps the manifest base.
- Step 6 starts with the selection test, which fails while `scripts/check-fast.ts` does not exist.
- In step 6, `check:fast` runs `dist --no-external` after the bundle. Then the drift test of the launcher set passes after a source edit.
- In step 6, with no `origin/HEAD`, `check:fast` runs `--changed` with no ref and says that it reads only uncommitted changes. The 20 s cap adds headroom to the 15.6 s of the sketch.
- In step 8, the note on line 85 says that the TLC runs start together and that the judge order does not change. The evidence and the ProofAdmission relation stay the same.
- In the first commit that it lands, the integrator replaces the B18 manifest with the B19 manifest. That manifest names the ProofAdmission model and holds a scope row for each changed path of that commit.
- When it lands each later step, the integrator adds the scope rows of that step to `.astack/proof.json`. It also runs `bun run bundle && bun run dist` and adds the generated files. Then `bun run check` passes on each commit.
- Step 8 adds the ADR 0005 notes to the manifest and sets its final claims.
- Step 3 proves its exit after the first checkpoint opens the draft PR.
- Run each timed check on the 18-core dev machine. Record the load average of each timed run.
- When another M2 PR merges first, merge main into this branch. Then run step 8 again.

## Proof

- `bun run check` passes on the session branch. The PR body gives the 3 timed runs, their load averages and the 3 `check:fast` runs against the 20 s cap.

## Premises

- No test file writes a path that another test file reads. Falsifier. A parallel run that fails for a reason other than a timeout.
- The required check and the hardening stop read only the pull_request run of the PR head. Falsifier. A required check that names a push run.
- The CI runner with 4 vCPUs holds 4 test workers with 3 TLC heaps of 512 MB each. Falsifier. An out-of-memory kill in a CI Check run.

## Risks

- At load 27, one test passed 20 s in a refocus run. A loaded machine can still fail the suite until B20 lands.
- A machine with an old node first and a newer node later loses the fallback to the newer node. Its hooks then exit 0 and check nothing. `astack doctor` reports it, and bun or a saved runtime avoids it.
- A product gate that runs the CLI on node 18 to 21 now exits 1 with the floor message. The `engines` floor is 22, and the CI of astack uses node 24.13.1.
