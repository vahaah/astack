## Goal

Goal. A listed name in public GitHub text gets a deny that names only its hash prefix. A second PR of one session and worktree needs a stacked base or a split instruction.
Decision. Can the owner trust that an agent cannot post a client name to a public repo, or split a plan into PRs, by mistake?
Done when. `[control:outbound-text]` and `[control:duplicate-pr-session]` deny the 14 public and 3 split forms and pass 15 controls, where main denies 0.

## How each step runs

- Each step starts with a test that fails for the reason of its candidate, in the same commit as its fix. The PR shows each red run first.
- Step 1 moves code with no change of behavior, so the old suites are its proof, with no red run.
- Steps 1, 4, 6 and 9 serve review K5, and steps 2, 3, 5 and 7 serve review K4. Each candidate owns its commits.
- A step proof that spawns the launcher starts with `bun run bundle`. Then the worker restores the bundle with `git restore`.
- The 9 suites of the Baseline are the 6 old test files of step 1, and guards, dispatch and hook in tests/astack/.

The forms.

- The hook tests use the example list in a temp state folder, a fake visibility and a fake open list. Each text holds a listed name.
- The gh forms are an issue create with `--body`, `--repo` or `GH_REPO`, a PR create with `--body-file`, and an issue comment.
- They also hold a PR comment from a heredoc, a PR title edit, a PR review, and `gh api` with `-f body=` and with `--input`.
- The MCP forms are a GitHub `create_issue` and `add_issue_comment`, a host `pull_request_create` with no repo field and a host `pull_request_respond`.
- The controls are an issue to `acme/private`, a clean text, `--body "$TEXT"`, a Linear `save_issue`, `gh issue list` and a private comment.
- After a first create of `dev/one`, the open list gets #1710. Then `dev/two`, a `Part of #1710` create in another session and a host create get the deny.
- The split controls are the first create, the stacked base `dev/one`, a create after "Split this work into a second PR." and a second worktree.
- They also hold a `Part of #1710` create on the stacked base and after the split, two creates of a new session and a `Part of #1709` link.

The outbound hook.

- `outboundWrites` gives the subject, the target, the texts and the body files of each write. It reads the gh flags with its own table.
- The target is `named` with a slug, `remotes` with the folder, or `unknown`. A graphql call gives `unknown`.
- `gh api` is a write with a method other than GET, or with a field. Each `@file` and `--input` file is a body file.
- An MCP write tool has a write verb in its name, such as create, update, add, push, comment, respond or review.
- The handler reads each body file from the disk, as D11 says. On a hit, it reads the remotes and the visibility of each slug.
- `outbound(visibility)` makes the handler, and `handler` binds `visibilityWithGh`, as `duplicatePr(list)` does.
- `visibilityWithGh` runs `gh api repos/<slug> --jq .visibility` with a 4 s timeout. Each other answer gives `unknown`.
- Its `failed` verdict denies each GitHub text write that the parse finds. The reason names the hash prefixes and each public or unknown slug.

The split rule.

- `SessionPrs` holds `split` and `opens`. An open holds the root, the repo, the base and the head.
- grant.ts exports its clause reader and `NEGATIONS`, and `mergeGrantIn` keeps its output. session-prs.ts saves as the grant store of B29 does.
- Step 7 adds `prompt` to the events of duplicate-pr. A person's prompt saves `split` and keeps `opens`.
- The base is `--base`, else the branch of `origin/HEAD`. The repo is `--repo`, `GH_REPO` or the MCP repo, else the origin slug.
- A host tool with create and pull request in its name gets the check. Its head is the `head` field, else the current branch.
- The deny keeps "one plan is one PR" and names the open PR. It says to push to that branch, or to stack the PR on it with `--base`.

- Step 8 adds the outbound row, the `deny sync` lines and the docs/adr/README.md row. It updates design.md:118 and the throw lines of README.md:48 and :482.

## Premises

- No host session runs two `gh pr create` calls at the same time. Falsifier. A lost open in the record after two parallel tool calls.
- Orchestrate and autopilot owners open each PR from their own worktree, or stack it. Falsifier. Two PRs to one base from one worktree.
- gh gives public, private or internal for each repo that the owner can read. Falsifier. An empty visibility answer.
- The owner runs `bun run deny sync` once on each machine. Falsifier. A public issue with a listed name after B10 merges.

## Risks

- A stale or missing state copy turns the check off with no message. `deny add` writes the copy, and a new machine needs one sync.
- A listed name in the public repo of that client gets a deny. The owner posts that text.
- Each hit costs one gh call of up to 4 s for each target that is not `PUBLIC_REPO`.
- The session record adds one file for each session that opens a PR, and nothing prunes it.
- An unattended session can never give a split instruction, so its second PR to one base needs a stacked base or the owner.
- The handler of step 9 reads the visibility with gh, so the premise at B35.md:171 is false. B35 must add it to its Out line at B35.md:58.
