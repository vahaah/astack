## How each step runs

- Each fix step starts with a test that fails for the reported reason, and the fix lands in the same commit. Each new test that runs a TLC triple takes `heavyTestTimeout`.
- Step 1 starts with the two-branch test. On trunk code the merge has 0 conflicts, and the run stops with ".astack/proof.json is missing" (proof.ts:145-151).
- A probe script merges two rewrites of `.astack/proof.json` and two new manifests, before and after the change.
- Step 5 starts with the issue #21 ADR, which cites D2 and lists the arrows only under D2. On trunk code it stops with "does not explain", because admission.ts:224 reads the D1 section.
- The search keeps each `*.json` path directly under `.astack/proof/` that `git ls-files -z --cached --others --exclude-standard` names and `lstat` finds as a regular file.
- With no path left, the run reads `.astack/proof.json` and keeps its missing stop. With `--base`, the search keeps the paths that `changedPaths` from the merge base names.
- With `--base`, a chosen manifest that the merge base holds stops at schema, also in ci-pins. Else a change can edit a merged manifest and keep its older base.
- A choice stop is a `schema` stop that exits 1, as the missing manifest does.
- After `proofBase`, one `git ls-tree` at the manifest base through `historyGit` lists the held manifests. Each one that `lstat` finds, also the chosen one, gives a `stale` stop.
- So does `.astack/proof.json` beside a folder manifest. Each stop says "delete <path>, which the manifest base <sha> holds".
- A path argument skips the search, and the deletion rule still applies under `.astack/proof/`. A found manifest prints `manifest: <path>` first, and the other two routes print no such line.
- `--summary` uses the same search, and the docs name the file after the `change` field.
- Contract. `manifestCandidates : (Root, DiffTarget, Path | undefined) -> Result<ManifestView, string>` and `manifestsHeldAt : (Root, ProofBase) -> Result<HeldManifests, string>` have spawn and fs-read. Git can fail, and the stop names the base.
- `chooseManifest : ManifestView -> Result<ManifestChoice, string>` and `staleManifests : (ManifestChoice, HeldManifests) -> Result<ManifestChoice, string>` are pure.
- The flow chains these four with `parseChangeProof` and `proofBase` by early returns on `Result`. It adds no composition operator, map or monad, so each new category law is not applicable.
- `proofRecordsAt` in ci-pins builds a `ManifestView` from `git ls-tree` at HEAD and its own diff, and then calls `chooseManifest`.
- `decisionSpan : (Text, Decision) -> Text | undefined` in src/astack/adr.ts is pure. The span ends at the next decision heading or at a heading of level 1 or 2. `adrMetadata` reads the decision text from it on both routes.
- `proofSections` gets the `decision` field of its reference. `ciProofRecords` passes that decision with each record.
- Invariants. `OneManifestPerChange` says that an admitted proof read one manifest, and its diff holds the folder manifest that it read.
- The tree then holds no folder manifest of the manifest base, and no `.astack/proof.json` beside a folder manifest. `CiRecordsSafe` keeps its words and gains the `manifest` check.
- Abstraction. `manifest.ts` hides the search order, the deletion rule and the fallback, and a caller knows one path or one stop. Without it, `proof.ts` and `ci-pins.ts` each repeat the choice rule.
- Step 4 gives the base observation a `manifest` field with the values one, fallback, several, none, held and beside. `ValidationPass` stops several and none at schema, and held and beside at base.
- Step 4 updates a registry negative in `formal/models.json` when its model edit changes the `original` text. It sets `ASTACK_TLC_JAR` to the jar in the astack cache.
- When B24 merged first, step 2 edits ci-pins.md only. When B16 merged first, step 3 edits the runbook that holds the old AGENTS.md:18 text.
- Step 2 removes proof-contract.md:3-4, :64-66 and :106-109, 96 words on main. It adds at most 96 words in proof-contract.md and ci-pins.md.
- Step 3 keeps the word count of change-proof.md:20, and it cuts adr.md:75-90 to the proof record duty.
- Step 7 runs only while question 1 keeps D13, and edits only ADRs 0005, 0006, 0009 and 0010.
- Step 8 writes `docs/adr/0016-each-change-carries-its-own-proof-manifest.md` with `Amends: 0005 D4`, its row in docs/adr/README.md and the Amended by line of ADR 0005. ADR 0016 holds no proof sections.
- Step 8 adds the named criteria, the controls, the glossary term Change manifest and the `contractOnly` glob `.astack/proof/*.json`. It runs `bun scripts/budget.ts --lower`.
- Step 8 deletes `.astack/proof.json` and writes `.astack/proof/<name>.json` last. Its model is ProofAdmission, and its negative control drops the manifest guard.
- After a merge of main, delete `.astack/proof.json` again when it comes back, and run step 8 again.
