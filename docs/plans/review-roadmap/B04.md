# One shell normaliser closes the guard bypasses, and fast-check proves the wrapper law

This block closes the shell bypasses of the merge guard and the destructive guard that the review found.
It gives the second part of the M2 demo.
`env git reset --hard` and `bash -c 'gh pr merge 1 --admin'` get the verdict of their plain forms, and a fast-check law proves it.
`LEFTHOOK=0 git push` gets the `--no-verify` verdict unless the gates passed at that HEAD.

## Context

- Review `E2`. `parseShell` splits a command only on `|`, `&`, `;`, `(` and `)` (src/astack/shell.ts:190-211). So the words `if`, `then`, `{` and `!` stay in the command.
- `parseShell` keeps a `$(...)` body, a backtick body and a `$x` as one dynamic word with the value "" (src/astack/shell.ts:88-97, 150, 180-189). It parses no step in such a body.
- So `git reset $(echo --hard)` reads as `git reset`. `x=.; git checkout "$x"` gives `git status` an empty pathspec, which fails and finds no loss.
- `shellSteps` resolves only a static `cd <dir>` (src/astack/shell.ts:280-283). So `cd /tmp && cd - && git reset --hard` reads a folder named `-`.
- The merge guard unwraps only `env` and `command`, and denies a dynamic word before `pr merge` (src/astack/hook/handlers/merge-guard.ts:34, 76, 95-113). The destructive guard unwraps no wrapper.
- `shellSteps` has 8 callers. They are the two guards and the comments, ste-artifact, types, pr-body, ticket and duplicate-pr handlers.
- `gitInvocation` never examines the program word (src/astack/git-command.ts:11-30). So `yarn commit -n` and `echo reset --hard && git status` get a false deny. `commitTargets` (ste-artifact.ts:79) uses it too.
- Review `E3`. `commandWords` drops the NAME=value words at the start (src/astack/shell.ts:257-265). So `gitReasons` never sees `HUSKY=0` or `LEFTHOOK=0` (src/astack/hook/handlers/destructive.ts:467-506).
- `docs/runbooks/publish.md:66` sets `core.hooksPath` to the tracked `.githooks` folder. That write turns hooks on.
- `workLoss` reads only reset, checkout, switch, restore and clean (destructive.ts:326-341). A named-file discard passes on purpose, as ADR 0010 D3 says at line 43.
- Review `E1`. `workLossReasons` has no test for a repo that the session made (destructive.ts:451-465). ADR 0010 D3 has no such exception. Index D5 named this rule, but index D12 replaced D5 and does not hold it.
- The REST form. `isApiMerge` matches `pulls/<n>/merge` only with a static number at the end of a word, and only the GraphQL name `mergePullRequest` (merge-guard.ts:33, 61-68). A full URL that ends in `/merge` already gets a deny.
- Review `C1`. `humanPrompt` is true for `source` set to `user` also in an unattended session (src/astack/ste/session.ts:25-33), and the decoder puts it in `event.human`.
- The turn handler returns at once in an unattended session, and its note needs the state folder and the ste hook group (src/astack/hook/handlers/turn.ts:18-31). `astack plan attended` reads only the environment (src/astack/cli/commands/plan.ts:63-66).
- No command runs the gates of a hardening profile. Only apply calls `profileGates` (src/astack/pr-review-profile.ts:829). The hardening run reads `.claude/pr-review-hardening.profile.md`, and its `gate.md` sets how a gate runs.
- The merge guard denies a chained `gh pr merge` and a NAME=value word before it (src/astack/pr/merge.ts:164-171). So `if C; then gh pr merge 12; fi` is a chain, and `A=1 gh pr merge 12` is not a plain wrapper.
- `tests/astack/hook.test.ts` and `ste-hook.test.ts` spawn `bin/astack`, which runs the committed `astack.js` (hook.test.ts:17, 37). So they test the bundle, not the source.
- SessionGuards models 16 git commands with no repo origin and no push (formal/SessionGuards.tla:35-51, 155-163). The claim boundary leaves the shell parser to the implementation controls (docs/reference/session-guards.md).
- The word budget caps equal the counts, 141,172 words in total (scripts/lib/budget.json). So an edit of skill text must keep its word count.
- The probe ran 63 forms through the two handlers. Its repo has one commit with `a.txt` and a tracked `.githooks/pre-push`, then a change in `a.txt`. It has a turn grant, a green PR 12 and no gate record.
- Deny, 21 wrapped resets. `git reset --hard` after `env`, `env -i`, `command`, `exec`, `time`, `nohup`, `nice -n 5`, `timeout 60`, `sudo`, `doas`, `stdbuf -o0` and `!`. Also `echo --hard | xargs git reset`, `{ git reset --hard; }`, `if true; then git reset --hard; fi` and `cd .. && cd - && git reset --hard`.
- The other wrapped resets are `bash -c 'git reset --hard'`, `eval 'git reset --hard'`, `echo $(git reset --hard)`, `cat <(git reset --hard)` and ``echo `git reset --hard` ``.
- Deny, 3 dynamic words. `git reset $(echo --hard)`, `M=--hard; git reset $M` and `x=.; git checkout "$x"`.
- Deny, 6 wrapped merges. `gh pr merge 12 --admin` after `time` and `sudo`, in `{ ...; }`, in `if true; then ...; fi` and in `bash -c '...'`. Also `echo 12 | xargs gh pr merge --admin`.
- Deny, 5 hook skips. `HUSKY=0 git push`, `LEFTHOOK=0 git push origin feature`, `git -c core.hooksPath=/dev/null push`, `git config core.hooksPath /dev/null` and `LEFTHOOK=0 git commit -m x`.
- Deny, 5 whole-tree discards. `git diff | git apply -R`, `git apply -R <(git diff)`, `git read-tree -u --reset HEAD`, `git checkout-index -a -f` and `git archive HEAD | tar -x`.
- Deny, 5 REST merges. `gh api -X PUT` on `repos/o/r/pulls/12/merge?merge_method=squash`, `repos/o/r/pulls/12/merge/`, `repos/o/r/pulls/$PR/merge` and `"repos/o/r/pulls/${PR}/merge"`. Also `gh api -X "$M" repos/o/r/pulls/12/merge`.
- Deny, 5 GraphQL merges. A `-f query=` field with `enablePullRequestAutoMerge`, `-F query=@merge.graphql`, `-f query="$(cat merge.graphql)"`, `--input body.json` and `cat body.json | gh api graphql --input -`. Both files hold `mergePullRequest`.
- Keep, 7 plain forms. `git reset --hard`, `git checkout .`, `git push --no-verify`, `gh pr merge 12 --admin`, `gh api -X PUT repos/o/r/pulls/12/merge`, the same `PUT` on its full URL, and a `-f query=` field with `mergePullRequest`.
- Pass, 6 forms. `yarn commit -n`, `echo reset --hard && git status`, `git show HEAD:a.txt > a.txt`, `git config --get core.hooksPath`, `git config core.hooksPath .githooks` and `cd "$dir" && git status`.

## How each step runs

- Each fix step starts with a test that fails for the reported reason. The fix lands in the same commit.
- Step 1 commits the 63 probe forms of the Context as `tests/fixtures/guard-bypass.json`, each with its expected verdict. Each later count comes from that file.
- The wrapper list is `env`, `command`, `builtin`, `exec`, `time`, `nohup`, `nice`, `timeout`, `sudo`, `doas`, `stdbuf` and `xargs`. A wrapper flag outside the known set makes the step unreadable.
- The guarded verbs are reset, checkout, switch, restore, clean, push, commit, the D7 verbs and `config` of `core.hooksPath`.
- A guarded verb with a dynamic flag, operand, `-C`, `-c`, `--git-dir` or `--work-tree` word is unreadable. The value of a value flag of the verb, such as `-m` or `-b`, stays readable.
- Step 1 keeps each NAME=value word on the step for `setsEnv` and step 9.
- The step proofs run the suites that import the source, because the 2 launcher suites test the committed bundle. Step 11 runs `bun run bundle` and `bun run dist`, and then the launcher suites.
- Step 2 follows the hardening `gate.md`. It exports `CI=true` and the `ci_env` values, and it puts the `tools` versions first on `PATH`. It runs the prerequisites and the `setup` commands in the `after` order.
- Step 2 applies a gate by its `when_changed` globs against `git diff --name-only --no-renames <base>...HEAD`. The record names each gate that ran and each gate that did not apply.
- Step 6 uses its own wrapper list. Cut `sudo` from the list in `src/astack/shell.ts` by hand. Run the property. It must fail with a counterexample. Put that output in the PR Verification. Then put `sudo` back.
- Step 7 reads a static `--input` file or `@file` field, and looks for the 2 mutation names in it.
- Step 9 reads the record of step 2. A push with `--all`, `--mirror`, `--tags` or a source that does not resolve gets the owner gate.
- Step 11 adds the criteria `SG-plain-form`, `SG-dynamic-word`, `SG-api-merge`, `SG-hook-skip` and `SG-gates-run`. It writes the proof manifest last, because its scope lists each path that the session changes.
- Step 11 adds these arrows to ADR 0010. `shellSteps` and `gitInvocation` stay pure. `destructive : HookCall -> Verdict` gets fs-read, spawn and env, because it reads the gate record.
- `gatesRun : (Profile, Base, Worktree) -> GateRecord | GateStop` has spawn, fs-read, fs-write and env. The `turn` handler keeps its effects, and its new note reads only `event.human`.
- The guards still run side by side under `combineAll`, so no composite arrow is new. The new law is the wrapper law, `verdict(w c) = verdict(c)`. The model takes the plain form as given.

## Risks

- The plain-form reader changes the steps of each of the 8 handlers, so a wrapped commit or write can get a new deny. Step 1 runs the source suites of those handlers.
- The dynamic-word rule denies `git push -u origin "$(git branch --show-current)"`. The deny asks for the branch name or `HEAD`, so the agent can run the plain form at once.
- An agent can write the green HEAD record in the state folder. So the record is a guard against mistakes, as B01 D8 says.
