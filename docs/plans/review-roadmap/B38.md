## Goal

Goal. A broad discard passes in a repo or worktree that this session made, and each other repo keeps the deny.

## How each step runs

- Each step starts with a test or a TLC run that fails for the reason that the step fixes. Step 6 starts with the probe case, which gets a deny on main.
- Step 1 puts `madeRepoTarget` beside `gitWords`, because it needs the `dynamic` flag of each word. It adds a value flag list for `init`, `clone` and `worktree add`.
- `git init` with no folder takes the folder of the step. `git worktree add` takes its first operand after the flags.
- A clone with no folder takes the text after the last `/` or `:`, with no slash, `/.git` or `.git` at its end. The test compares each case with real git.
- Step 2 keeps the record at `<state>/session-repos/<session>.json`. It writes the file with a temp file and a rename, as `saveGrant` does.
- A pending entry holds a path and its free target. That is the call time less one second for a missing path, or the identity of an empty folder. A bound entry adds an identity with a device, an inode, a birth time and a git dir. The settle does not read the verb, so the entry holds none.
- The path is `canonicalFile` of the target, which step 2 exports. The probe runs `git rev-parse --show-toplevel --absolute-git-dir --git-common-dir` in the path.
- `settleRepos` and `sessionRepoAt` get the probe result as a value, so they spawn nothing and read no file.
- `loadSessionRepos` parses the file at the edge. A failed read, stat, readdir, spawn or parse gives no record, no identity or no target, and nothing throws.
- Step 3 adds `Repos`, `Records`, `Settle(r, at)`, `Exempt(r)` and the flag `sessionDenied`. `MakeRepo` needs `repo = "none"`, sets `record` to pending and `window` to TRUE, and lets the call run or not.
- `Shell` stands for each later shell call. It settles the record and sets `window` to FALSE. `RunGit` settles first too.
- `Appear` puts a repo of another process at the path, also over a session repo. It needs `~window`, which is the first premise.
- `RunGit` sets `sessionDenied` when it denies a broad discard in the repo of the bound record. `DenialNeedsLoss` stays as it is, over each repo.
- Each other concern keeps `repo` and `record` at none and `window` at FALSE. Step 3 adds `SessionRepoPasses` to the cfg and to the registry in one commit.

## Premises

- No other process makes a repo at a pending path between the call that makes it and the next Bash call of the session. Falsifier. A discard that passed in a repo that the owner or another session made in that window.
- The host runs a Bash call that writes to its end before the PreToolUse hook of the next Bash call. Falsifier. A settle that drops the record of an init that ran, so a later discard in that repo gets a deny.
- The host keeps one session id for the life of a session, also across a compaction. Falsifier. A transcript where the id of the session changes between the init and the discard.

## Risks

- A denied init leaves a pending path. When another process makes a repo there before the next Bash call, the settle binds it. The model takes this window as a premise.
- The window lasts until the next Bash call of the session. An Edit, Write or MCP call and a permission prompt do not end it.
- When the save of a bind fails, the file keeps the pending entry. The next call settles it again, so the window lasts until a save succeeds.
- A file system can have no birth time. There, a new folder at the path of a deleted session repo can reuse its inode and match the record.
- Two hook processes of one session can save the record at the same time, and one entry can go. A lost entry only gives a deny.
- A session repo can hold files that another process writes into it later, and a discard there passes.
- An agent can write the record file by hand. ADR 0028 says that the record is a mistake guard, as ADR 0011 D6 says for the grant file.
