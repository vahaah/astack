## How each step runs

- Each fix step starts with a test that fails for the reported reason. The fix lands in the same commit.
- Step 2 first turns on the fences and records the validate run that fails with the 20 findings. Then it fixes the templates in the same commit.
- A fence of data lines takes a data info string from the pinned list, such as `tsv`. The PR body names each such fence.

- A template rewrite keeps the word count of its skill at or under its cap. Run `bun run budget` after each rewrite.

- After each landed step, the integrator runs `bun run bundle && bun run dist` and adds the generated files to that commit. Then `bun run check:drift` passes on each commit.
- The name of each test that guards a criterion holds `[control:<id>]` with the criterion id in lower case.
- Step 8 first runs `bun run check:proof` on a draft ADR and manifest, and fixes each proof finding before it writes the model.
