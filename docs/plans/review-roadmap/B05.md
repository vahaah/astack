## How each step runs

- Each code step starts with a test that fails for the reported reason. The fix lands in the same commit.
- Steps 1, 4 and 8 make each fixture from a real run of the pinned tla2tools 1.7.4 with `-tool`. Each fixture uses a synthetic path, because `bun run neutral` refuses a local path.
- Step 4 adds a model that extends a `Dep` module with a parse error. Step 8 adds a temporal model with weak fairness, so its trace has a 2122 record.
- Steps 2 and 5 link the `Category and abstraction` and `TLC execution` headings, and step 3 keeps both. Step 7 maps each of the 7 stages to one heading.
- card.md names proof-contract.md through `astack skill-path`, because `rules/astack.md` is a copy outside the plugin. Step 2 runs `bun run build` for that copy.
- Step 2 cuts mode text before steps 5 and 6 add mode text, so each commit passes the budget gate. When a step passes a cap, it shortens its own new text.
- Step 6 updates the two anchored pins of the ratification test. One names the ratification history, and one names `ignored/proof.md`. The index-binding CLI test expects the index.
- Step 9 tests D5 on a synthetic run end. A CLI test needs a deadline above 4 s, and B19 cuts that deadline to 200 ms.
- Each new test name carries its control id. Step 11 links the ids to the criteria in `docs/reference/change-proof-contract.md`.
- CP-16 covers the line ends (`tlc-line-ends`), CP-17 the SANY location (`tlc-sany-location`) and CP-18 the trace (`tlc-violation-trace`).
- CP-19 covers the stale paths and the timeout progress (`proof-stale-paths`, `proof-timeout-progress`, `proof-timeout-stdout`).
- CP-20 covers the stop section and the example (`proof-stop-section`, `proof-stop-heading`, `proof-example-parses`, `proof-example-keys`).
- The spec-drift check refuses a control id that two tests declare. So the runner test, the heading test and the key test each take their own id.
- Step 10 runs `bun scripts/budget.ts --lower`. The PR body lists each cap before and after, so the reviewer can see that no cap rises.
- Step 11 takes ADR 0014, the highest number plus one, and adds its row to `docs/adr/README.md`. B01 names ADR 0011. The ADR links the model, its config and the matrix, and names its typed witness file.
- The typed witness `proof.ts` names `judgePositive`, `judgeNegative`, `snapshot` and `admitChangeProof`, so the manifest declares these 4 arrows. The ADR also explains `parseTlcRecords`, which both judges call.
- Step 11 writes the proof manifest last, because its scope lists each path that the session changes. When another PR merges first, merge main. Then run steps 10 and 11 again.
