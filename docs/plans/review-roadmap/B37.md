# The guards deny each stdin, fd, `$` and environment config form of the security review after B04

This block closes the six findings of the security review that came after the B04 cutoff.

The guards stop agent mistakes and are no security boundary, as ADR 0011 D6 and B01 D8 say.

Findings 1 and 2. The fd of a redirect and of a heredoc.

- `parseShell` reads a redirect fd as a string, and it counts a stdin source only for `<` with fd `0` or none (src/astack/shell.ts:299-310).
- So `00<f` and `0>&3` add no source. A dup such as `<&3` records no redirect (:311-314).
- The `<<` and `<<<` branches call `endWord` first, so `bash 0<<'EOF'` reads as `bash 0` with no script (:276-297).
- `readsStdin` marks stdin dynamic only on a second source (:114-117). `stdinScript` reads no script with no stdin text and no pipe (:652).
- `endCommand` drops a redirect after `)` (:120, :266). `plainForm` drops the step of a redirect after `}`, `done` or a bare `exec` (:551, :782).
- So `bash < f`, `bash <&3`, `{ bash; } < f`, `(bash) < f` and `exec 0<f; bash` give a readable `bash` with no body.
- ADR 0010:52 denies each other script on stdin with no search of its text. The code meets that rule only for a pipe.
- Root cause. The parser keeps only heredoc and here-string text as stdin and compares fds as strings. So an unread stdin source leaves the step readable.

Finding 3. Unknown `$` forms.

- `EXPANSION_START` is `[\w{@*#?$!=~^-]` (shell.ts:31). The `$` branches use it (:201, :231), and each other `$` falls to the literal branch (:318).
- So `$"pr"` reads as the static word `$pr`, and the merge guard reads `gh $"pr" merge 12` as no merge. Bash reads `$"pr"` as `pr`.
- zsh reads `$"pr"` as `$pr` and `$+x` as `0` or `1`. So the bash read gives only a false deny there, and `gh pr $+x merge 12` is a fail-closed row.
- Root cause. The parser treats an unknown `$` form as literal text, so a word that the shell changes looks static.

Finding 4. Git config from the environment.

- `gitWords` reads config only from `-c` and `--config-env` (src/astack/git-command.ts:35-68).
- `skipForm` reads only a static `HUSKY` or `LEFTHOOK` skip, and `exportedSkips` reads only an `export` step (src/astack/hook/handlers/destructive.ts:576, :722-736, :893-898).
- git reads the pairs of `GIT_CONFIG_COUNT`, and also `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_SYSTEM` and `GIT_CONFIG_NOSYSTEM` (git-config(1)). Each can set or drop `core.hooksPath`.
- An `include.path` or `includeIf.<cond>.path` key loads a file that can set `core.hooksPath`. git 2.56.1 read it through `-c` and through a pair.
- `turnsHooksOff` and `hooksPathReasons` test only `HOOKS_PATH_KEY` (git-command.ts:79, destructive.ts:705-712, :770-799).
- Root cause. The guard reads the git config only from command flags and for one key. It reads an export only from the `export` form.

Finding 5. The gate record.

- `GateRecord` holds the head, the base, its tip and the gate names at `<state>/gates/<head>.json`. Its loader checks only types and the head (src/astack/gates.ts:27-33, :267-318).
- `astack gates run` reads the profile from a clean checkout (src/astack/cli/commands/gates.ts:39-71). So a commit that drops a gate still gets a record.
- `runGates` picks gates with the diff `<base>...HEAD`, which starts at the merge base (gates.ts:132-135).
- The destructive handler reads only shell events (destructive.ts:902). It returns at once when the text names no `supabase`, `git`, `npm`, `pnpm`, `yarn` or `bun` (:904-905).
- A probe passed a Write call, an `echo` redirect and a `cp` into the gate folder.
- ADR 0011:152-156 calls the merge guard no security boundary. ADR 0010 says nothing of this kind for the gate record.
- Root cause. The record names no profile, and nothing stops a write of the record.

Finding 6. The `core.hooksPath` target.

- `tracksHooks` passes a target when HEAD holds each active hook name there as a 100755 file (destructive.ts:648-702). It compares no bytes and reads no working-tree change.
- It also needs at least one such hook there (:702). guards.test.ts:638-663 hold 5 deny rows for a target with no tracked hook.
- guards.test.ts:788-797 pass a target with hooks that exit 0, while the active hooks exit 1.
- Root cause. The check compares hook names, not the hooks that git runs.

## Risks

- The fail-closed `$` rule denies a guarded git verb with a word such as `$.50` outside a message flag. A `gh api` write with that body gets the endpoint deny (merge-guard.ts:217-219).
- The STE commit check skips a message with an unknown `$` form, as it skips each dynamic message (ste-artifact.ts:84).
- A shell that reads stdin from a file gets the stdin deny when the text names git, supabase or a package manager.
- The merge guard also denies it when the text holds `gh`, `pr merge`, `*`, `?`, `[` or `{` (merge-guard.ts:53, :392).
- A stdin redirect on a group or a bare `exec` marks each shell step of the text. So a readable shell beside it gets a false deny.
- Each command with the word `gates` pays the parse cost of the destructive handler.
- `astack gates run --base HEAD` binds the record to the profile of HEAD. The ADR names this limit of a mistake guard.
- An old gate record has no profile blob, so the first hook-skip push after the update gets the owner gate.
- A gates run with another `ASTACK_STATE_DIR` writes a record that the hook does not read, as today.
