## How each step runs

- Each step is one commit for one candidate. It starts with a test that fails for that reason. The PR shows each red run first.
- A step proof that spawns the launcher starts with `bun run bundle`. Then the worker restores the bundle with `git restore`.

The staged read.

- Step 1 adds to `SimpleCommand` the `&&` or `||` before each command. It exports `stagedText`, `StagedText` and `DiskText` from shell.ts.
- `StagedText` is `text`, `unread` with the disk text, or `missing`. A dynamic word for `--body` or `--body-file` gives `missing`, which skips with no note as today.
- A certain write to the resolved path replaces the text, and an append joins it. A write is certain when its pipeline starts an and-or list.
- A write is also certain when `&&` comes before it and only `&&` comes between it and the body step.
- Each other write gives unread. So does a write inside if, case, a loop or a function, in the pipeline of the body step or in the background.
- Heredoc text counts for D3 only in a step that `fileWrites` does not parse. The reader steps are cat with no redirect, head, tail, grep, wc, ls, test, `[` and astack.
- Step 7 makes `ghBody` take a reader `(path) => StagedText` and return `StagedText`. It moves each caller of `ghBody` and `commitMessage`, and the old disk read goes.
- ste-artifact logs the note as one `advise` event with rule `unread-body` and no path. `--body-file -` keeps the stdin text.

The chain line.

- Step 2 exports `chainSteps` from shell.ts, and `judge` in dispatch.ts calls it. It gives the first word of each top-level command of `parseShell` that is not an env assignment.
- chainSteps is in shell.ts, because `astack check effects` gives each step of dispatch.ts the effects of that module. A pure step there gets advice.
- The line reads "Nothing in this command ran. It had 2 steps. git, git." It gives no advice. `combine` and its laws stay, because the line comes after `combineAll`.

The text steps.

- Step 3 exports `sameRepo` from gh.ts, and the handler reads origin through `originSlug`. `mcpPr` calls `sameRepo` in place of its own compare.
- Step 6 counts lines that start with `|` and code lines inside fences. The note keeps the 40-line cap and links the comment from Verification.
- Step 9 cuts mode/SKILL.md:86-89 and the `check ste` sentence of create-pr.md:32, write-docs/SKILL.md:154 and write-ticket/SKILL.md:91.
- Step 9 adds one card line. "When the host runs no astack hook, run `astack check ste <file> --surface <reply|commit|pr|ticket>` on each draft first."
- Step 10 updates design.md sections 3, 7 and 9.3 and :409. The plugin README:333 gets the base name lookup.

The record.

- Step 10 takes the next free ADR number, 0033 today, and examines it again when B37, B29, B30 or B35 merges first.
- ADR 0033 holds D2 to D6 with their rejected options. It cites ADR 0022 for the note event and holds no proof section.
