## How each step runs

- Step 1 starts with the isolation tests, which fail while `tests/git-template.ts` does not exist.
- The name of each test that guards a criterion holds `[control:<id>]` with the criterion id in lower case, such as `[control:fx-isolate]`.
- Contract. The objects are `FixtureSpec`, `Template` and `RepoCopy`, and each arrow links to its symbol in `tests/git-template.ts`.
- `buildTemplate : FixtureSpec -> Template` has spawn and fs-write. It writes one `git fast-import` stream into a `mkdtemp` folder, then renames that folder.
- `copyTemplate : Template -> RepoCopy` has fs-read and fs-write. `rewriteConfig : RepoCopy -> RepoCopy` has fs-read and fs-write, and points each template path of the copied git config at the copy.
- `refreshIndex : RepoCopy -> RepoCopy` has spawn, and runs `git update-index --refresh`. `commitTree : (RepoCopy, BranchSpec) -> RepoCopy` has spawn and fs-write.
- `commitTree` writes one `git fast-import` stream and runs one `git checkout -f` at fixed past dates, so no arrow reads the clock.
- `copyRepo` calls `copyTemplate`, then `rewriteConfig`, then `refreshIndex`. It uses plain calls and adds no composition operator, map or monad, so each category law is not applicable.
- Invariants. `TemplateUnchanged` says that a write in a copy never changes the template or its origin. `CopiesDisjoint` says that it never changes another copy.
- `CopyIndexClean` says that each new copy passes `git diff-index --quiet HEAD`. `NoPartialTemplate` says that a build that stops leaves no template at its final path.
- Abstraction. The helper hides the git object layout, the config path rewrite and the index refresh. A caller knows that a copy is a new repo with the template commits and its own origin.
- The deletion test of the helper. Without it, each of the 5 files keeps its own chain of init, add, commit and push calls.
- FX-ISOLATE maps to `TemplateUnchanged` and `CopiesDisjoint`. FX-INDEX maps to `CopyIndexClean`, and FX-ATOMIC maps to `NoPartialTemplate`.
- `docs/reference/test-fixtures.md` declares FX-ISOLATE, FX-INDEX, FX-TREE, FX-ATOMIC, FX-OWN-DIR and FX-REAL-SCAN, because a test guards each of them.
- FX-COST, FX-BUDGET, FX-NO-RAISE and FX-TIME come from timed runs and shim counts, and the PR Verification holds them. The coverage check needs a test control for each criterion of a spec.
- Steps 3 to 7 change the cost and keep the behaviour. Each keeps each expected value byte for byte.
- In steps 3 to 7, the red check is the git count of a PATH shim on trunk. The green check is the new count.
- Keep the shim outside the repo. The PR Verification gives the shim script and the trunk and branch counts of each changed file.
- Step 3 keeps the symbolic link entries of the ci-pins fixtures. Step 4 keeps `core.autocrlf` set to false in its template.
- Step 5 makes the harness template once for each module instance with `mkdtemp`. Then two parallel workers never build into one folder.
- In step 5, `removeWorlds` also removes the template, and `createWorld` rebuilds it when it is gone. A serial run of pr-head and hardening-consistency shares one module instance.
- Step 2 moves the catch of `ProjectConfigError` into the function that the tests call.
- Step 2 starts with the combined test. Its expected lines are the 9 lines of the Context probe.
- The combined test replaces the fallback key case, the schema error case, the two `.env` cases and the exception rows test at `:139`.
- The clean example, the STE case, the ste.mode case and the no-config case stay. Each calls the main function of the script in process with a stub scan.
- Step 8 adds `tests/heavy-test.ts` with `heavyTestTimeout` set to `20_000`, the value of the B19 raise. Each budget test imports it.
- A load average is the 1-minute value that `uptime` prints just before each run starts.
- Step 8 runs 3 timed parallel runs and records the load average before each. It also runs the 6 heavy files in series on trunk and on the branch.
- A test outside the D6 classes that passes 4 s in one run stops step 8 for a diverge round.
- In step 9, the model has one template, its origin, two copies, a build that can stop and a push from a copy. The negative control keeps the template origin in a copy.
- Step 9 writes the proof manifest last, because its scope lists each path that the session changes.
- Step 9 takes the lowest ADR number above 0021 that main does not hold and no brief names. Today that is 0022. The integrator records that number in the index before step 9 runs.
- When another M2 PR merges first, merge main into this branch. Then run step 9 again.

## Premises

- B19 cuts the TLC triple from 3.4 s to approximately 1.2 s, as the refocus measured. Falsifier. A serial run after B19 where `[control:proof-valid-triple]` still takes 2 s or more.
- No command under test reads a path that a template copy changes, such as the reflog text of a clone. Falsifier. A test that passes on trunk and fails on a copy for a reason other than the origin URL or the index.

## Risks

- A CI runner is slower than the dev machine. A run on 4 workers passed each test at the 5 s default here. When CI reports a timeout, step 8 stops for a diverge round.
- At a load average over 20, a parallel run can still pass 5 s on one test. Step 8 measures under 20 and records each load.
- B05 and B09 take the next free ADR number. The integrator records one number for each block in the index, so two M2 PRs never write one number.
