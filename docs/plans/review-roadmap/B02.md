# The proof of a PR stays valid when main moves

This block removes the stale proof stop that each open PR gets after a merge to main.
It gives the second part of the M1 demo.
An older proof of a PR passes after main moves.

## Context

- Review `A1`. `prove` in `src/astack/cli/commands/check/proof.ts` stops with "stale" unless the `--base` ref resolves to `proof.base`.
- `scripts/check-proof.ts` passes `--base origin/<base>` on each PR run. So the proof of each open PR fails when main moves.
- `changedPaths` and both snapshots read from `proof.base`. After a merge of main into the branch, the paths of main enter the scope check.
- Push and release runs pass no `--base`, so they diff from the manifest base. With an older manifest base, the paths of other merged PRs enter the scope check of the push run on main.
- `ciProofRecords` in `src/astack/change-proof/ci-records.ts` also needs the manifest base to equal the merge base.
- `changedPaths` and `ci-pins` read git with plain `runGit`, which follows replace objects. `readIntegrationHistory` uses `historyGit`.
- `readIntegrationHistory` binds ratification history to the manifest base, as ADR 0007 says. A move of main that edits a governing ADR stops it.
- Step 6 of the mode refresh reference and step 7 of the modernize skill tell the agent to set a new base by hand.
- Two projects logged 59 and 57 stale proof stops in one week.
- `formal/ProofAdmission.tla` has no base variable and no action that moves main.

## Goal

Goal. A PR whose proof names an older main commit passes `astack check proof --base origin/main` after main moves.
Decision. Must an agent prove each open PR again after each merge to main?
Done when. A test branch with a proof at the parent of the main tip passes the proof against the main tip. Today `prove` stops it as stale.

## Scope

- In. One base pair at the git edge for `check proof` and `check ci-pins`. The manifest base stays for ratification, and the merge base feeds the diff and the snapshots.
- In. A base for each push and release run of `scripts/check-proof.ts`.
- In. A stop that names the ADR, both commits and the repair when main edits a governing ADR.
- In. ADR 0012 with the base rule, an ADR 0005 header that names ADR 0012 and ADR 0008, and the base stage of `formal/ProofAdmission.tla`.
- In. The deletion of the manual base steps, and the proof text in the README and `proof-contract.md`.
- Out. The contract-only tier and the model registry. B06 builds them and records them in ADR 0015.
- Out. The per-change manifest. B07 builds it and records it in ADR 0016.
- Out. The TLC error text. B05 owns it.

## How each step runs

- Each step starts with a test that fails for the reported reason. The fix lands in the same commit.
- Step 6 writes the proof manifest last, because its scope lists each path that the session changes.
- When another M1 PR merges first, merge main into this branch. Then run step 6 again.
- Use the branch `sketch/review-roadmap` as the design reference. The sketch has no push base and no ratification text, so steps 3 and 5 go past it. Never merge it.

## Premises

- On a PR run, the merge base of the checkout and `origin/<base>` is the base tip. Falsifier. A PR run where `git merge-base HEAD origin/main` differs from `origin/main`.
- A merge to main is a squash or a merge commit, so the first parent of HEAD is the old main tip. Falsifier. A rebase merge. Then the push run diffs only the last commit, which is narrower but still admits.
