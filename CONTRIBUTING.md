# Contribute to astack

Read `AGENTS.md` for the code rules and generated files.
Read `docs/design.md` before a layout or hook change.

## Local checks

Use the Bun version that the CI workflow pins.

```sh
bun install --frozen-lockfile
bun run check
```

Run `bun run check:drift` before a build to detect stale checked-in artifacts.
The command compiles the CLI in memory and compares every generated file.
It leaves generated bytes, executable bits, and modification times unchanged.
Run `bun run check` to rebuild and validate changed source.

Run the same check before a commit.
Record test counts and skipped checks in the pull request.
Do not weaken a check to make a change pass.

## Source changes

Change a renderer or source file before you rebuild its output.
Keep generated files in the same pull request as their source change.
Do not edit `upstream/`.
The frozen snapshots provide licence evidence and test data.

For a bug, reproduce the failure before its fix.
Keep that regression check with the fix.
Use synthetic fixtures for all captured data.

## Privacy

Keep private project configs and machine settings in a private companion.
Do not add customer names, credentials, captured identifiers, or personal paths to this repository.
Run the owner companion scan before a public release.
The public CI uses the synthetic companion and cannot identify every private client value.

## Pull requests

Describe the problem, the new behavior, and the verification.
Explain rollback when the change affects installed clients.
Name a skipped check and its reason.
Do not include private logs or tokens as evidence.

## Releases

Follow `docs/runbooks/publish.md`.
A public release starts from a scanned tree and a new first commit.
The owner creates the public repository and pushes its first commit.
